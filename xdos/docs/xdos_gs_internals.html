xdos_gs Internals

xdos-cpp / src/cli/main.cpp · C++17 · Apache-2.0

xdos_gs is the XDOS satellite's operator ground-station CLI: an interactive terminal program that loads the mission database (MIB), connects over TCP to the on-board computer (OBC) — or directly to subsystem simulators — and lets an operator browse, parameterise, send telecommands (TC) and read back decoded telemetry (TM) for six subsystems: ADCS, EPS, GPS, Payload, XLINK-S and UHF. This document explains every block and function of the program, derived entirely from the source code.

binary: build/xdos_gs entry: src/cli/main.cpp (2 942 lines) core lib: xdos_core launch: scripts/run_cli.sh
01 · Overview

What xdos_gs is, and what it is built from

The CMake target (CMakeLists.txt:63) compiles four translation units and links the shared xdos_core library:

From xdos_core it uses: the MIB loader (src/mib), the payload codec (src/codec/codec.cpp), the CCSDS TC and TM codecs (src/codec/ccsds_*.cpp), the five native framing modules (src/framing), the XLink codec and key catalog (src/subsystems), the session layer (src/session), the TCP transport (src/transport), and the EGSE bench protocol (src/common/egse.cpp).

The operator's mental model

The program is a loop over one idea: pick a message from the database, fill in its parameters, push it down a stack of encoders onto a TCP socket, then pull the reply back up the same stack and print it in engineering units. Everything else — the power bar, the CCSDS toggle, history, the LUT composer — is support machinery around that loop.

startup banner → connect → main menu (1…6 / p / g / c / ! / h / r / q)
  → pick subsystem → list TCs (filter, search, pages) → enter ID → params → send
  → TX/RX hex dumps + decoded TM → back to the list
02 · System context

Where the CLI sits on the network

By default (--via-obc) the ground station opens one TCP connection to the OBC bridge and multiplexes every subsystem over it — from the GS's point of view the subsystems are not buses but APIDs inside CCSDS frames. With --no-obc it instead opens one socket per subsystem simulator, reproducing the genuine bus-per-subsystem topology. Three side channels bypass the flight link entirely: the EGSE "umbilical" to the EPS sim, the EGSE status port on the OBC, and the LUT upload listener on the OBC.

03 · Startup

What main() does before the first prompt

main() (main.cpp:2760) runs a strictly ordered boot sequence. Each step degrades gracefully — a missing CCSDS profile or key file prints a warning and the CLI keeps working in a reduced mode.

  1. Winsock init. xdos::net::Startup — a no-op on POSIX, WSAStartup on Windows.
  2. Flag parsing. --no-color, --no-obc/--via-obc, --obc-host/-port, --xlink-host/-port/-key, --script FILE, --help.
  3. MIB load. mib.load_dir(find_mib_dir()) reads every mib/*.json alphabetically, then print_mib_stats() prints per-subsystem TC/TM counts.
  4. CCSDS TC codec. Loads mib/ccsds_tc.json; on success attaches it to the Session, records the ground-station ID into g_link_gs_id, and honours the profile's enabled_by_default flag.
  5. CCSDS TM codec. Loads mib/ccsds_tm.json into the file-scope singleton g_tm_codec, attaches it, and records the default radio-module ID into g_link_radio_id. The TM profile re-reads the TC profile so spacecraft ID and APID map can never drift between directions.
  6. XLink key catalog. Scans mib/xlink_keys/*.txt, loads the first parseable vendor file via xlink::KeyCatalog::load(), applies its first entry as the active 128-bit product key, and stashes the catalog in the xlink_catalog() singleton for the interactive picker.
  7. Banner + Logger. print_banner() shows the link mode; constructing Logger opens the timestamped session log file.
  8. Connect. connect_session() — see below.
  9. Script mode short-circuit. If --script was given, run_script() executes the file and the process exits — no menus, no power monitor.
  10. PowerMonitor. Constructed from the MIB + FlightConfig::load(), published through the global g_pm, and its 2-second background poll thread started.
  11. Main loop. Draw menu → read one line → dispatch on its first character (§05) — until q, then stop the monitor, disconnect all sockets and exit.

connect_session() (main.cpp:211)

Applies --xlink-key if present (warning on bad hex), then branches on the topology:

  • via OBC: calls sess.set_shared_link(true), configures the single OBC endpoint into the shared slot and opens it. Prints CONNECTED or a FAILED line with a checklist hint (kill switch, OBC booted, cabling, subnet, port).
  • --no-obc: configures ADCS/EPS/GPS/UHF at 127.0.0.1 on their sim ports plus the XLink endpoint, connects each and prints a per-bus OK/FAILED line. Payload is deliberately not configured — payload TC/TM is routed through the OBC only. Returns true if any bus connected.

find_project_root() / find_mib_dir() (main.cpp:2292)

The CLI can be launched from the repo root, build/, scripts/ or anywhere else, so resource paths are never CWD-relative. find_project_root() walks up from both the current directory and the executable's own location (/proc/self/exe on Linux, GetModuleFileNameA on Windows) and returns the first ancestor containing a mib/ or config/ directory. find_mib_dir() appends mib. The LUT composer anchors its config/ outputs the same way.

class Logger — the logging tee (main.cpp:77)

Every operator-visible exchange is written twice: to stdout with ANSI colour, and to a session log file named TCTM_Payload_MM_DD_HH_MM.txt (created in the CWD at startup). operator<< streams any value, prints it, then copies it to the file with ANSI escape sequences stripped (it skips from \033 to the terminating m), and flushes after every write so a crash loses nothing. Flows receive a Logger& and use it in place of std::cout for anything worth keeping.

05 · Main menu

The dispatch loop and every key

print_main_menu() (main.cpp:483) draws, in order: the live power bar (render_power_bar, §10), a row of per-bus connection dots (● connected / ○ down, from sess.connected()), and the option list. Options appear conditionally: 4 only when CCSDS is ON and routing via OBC, c only when a CCSDS profile loaded, ! only when history is non-empty. The loop in main() dispatches on the first character of the line:

123 ADCS / EPS / GPS → subsystem_flow()
4 Payload server → payload_flow() (needs CCSDS ON + via-OBC; otherwise prints why)
5 XLINK-S transceiver → xlink_flow()
6 UHF (437 MHz OpenLST) → subsystem_flow()
p Power control → power_flow()
g Binary rate-group LUT → binary_lut_flow()

Inside any TC listing the prompt accepts: a numeric ID, a spec-level ID (EP-3, UHF-4 — loose forms accepted), ?ID for details without sending (show_tc_details()), /keyword for name search, Enter for next page (20 per page) or back, b for back and h for show_tc_listing_help().

06 · Core mechanism

The telecommand pipeline, end to end

This is the heart of the program. When the operator confirms a TC, the flow calls send_and_report() (main.cpp:960), which delegates the wire work to Session and then renders the result. The full journey of one EPS command:

send_and_report() in detail (main.cpp:960)

  1. Flight-power preflight. Reads the PowerMonitor snapshot. If the OBC is not On (with a tailored hint: turn the kill switch on, or wait for boot/sequencing) or the target subsystem's PDU channel reads 0, it warns "⚠ …" and asks send anyway? [y/N] — the doomed command is abortable before it hits the wire.
  2. Three send paths. wrap_log=true → GPS GET, rebuilt as LOG(message_id=…, trigger=4 ONCE) through send_tc(); empty_payload_request=true → ADCS GET via send_tm_request() (empty-payload TC frame carrying the TM's id); otherwise a plain send_tc().
  3. Pre-send summary. For SETs, a "Setting: name=value, …" line built with format_value(); EPS channel-mask bytes are suppressed and replaced by a "channels ON = CH4 (ADCS), …" summary resolved through the MIB channel map. ACTIONs get an "Action: name" line.
  4. Wire dumps and link identity. CCSDS header summary + inner native bytes (if wrapped), full TX hex, log_tx_link(); then RX hex, log_rx_link(), log_tm_frame_header() (SCID, RM, master/sub frame counters, APID, sequence, payload size, CRC verdict, UTC timecode, GS-ID).
  5. Decoded-value rendering — the subject of §09.
  6. ACK banner. For SET/ACT replies containing a Status field: Status==1 → "✓ Acknowledged by <board> — values written / action executed", else "✗ Rejected (Status=N)".
  7. Timing. Wall-clock "Sent hh:mm:ss" and the measured RTT in ms.

Session — the five send paths (src/session/session.cpp)

MethodUsed byBehaviour
send_tcall standard TCsMIB lookup by name, node→RS485 address resolution (EPS broadcast fallback), codec::encode, then transact().
send_tm_requestADCS GETsEmpty payload; the frame's msg_id is the TM id — CubeSpace idiom for "send me this TM".
send_tc_dataPayload 600/601/602Caller supplies the data field verbatim (variable-length name/args the fixed-offset codec can't express); framing + CCSDS as usual.
send_raw(raw hex path)No MIB, no native framing; bytes go into TC-Data directly if CCSDS is on.
send_xlink_tcXLINK-S flowBypasses codec+framing entirely: xlink::codec::encode_frame builds key+event+data; reply is reassembled across TCP segments (2.5 s deadline, 40 ms quiet-window) because a 1432-byte TM frame can arrive fragmented; response trimmed to 20 B header + U32-aligned RSP length; ACK/NAK flags surfaced (error="XLink NAK").

transact() implements steps 3–9 of the diagram for the first four paths. strip_tm_padding() knows each subsystem's frame delimiter: Payload's 3-byte header declares its exact length, GPS's OEM7 header gives header-len + payload-len + CRC32, UHF's ESP length byte is exact, EPS trims at the terminal 0x01, ADCS at the 1F FF trailer, and XLink passes through untrimmed (fixed-offset decode ignores padding). The ExchangeResult struct returned to the CLI carries every intermediate representation — tx_payload, tx_native, tx_frame, rx_frame, rx_native, rx_payload, decoded JSON, CCSDS/TM header decodes, RTT and an error string — which is what makes the CLI's rich reporting possible.

Shared-link indexing

Session::idx() maps every subsystem to slot −1 (kObcIdx) when shared_link_ is set, so all six subsystems share the one OBC socket; in --no-obc mode each subsystem gets its own slot and socket. connect(), connected() and transact() all go through this indirection — the flows never know which topology is active.

payload_flow() — Payload server via OBC (main.cpp:1598)

Menu-driven from mib/payload.json. A payload command is a 3-byte [type|cmd|len] header + data, carried under APID 5 with the command ID mirrored into CCSDS TC-ID. Entry forms are hand-built per command ID:

CmdNamePrompted input
545 / 546Container ON / OFFprompt_payload_id() — 0 MSI, 1 SCANWAY, 2 SAR; sent via send_tc with a one-byte "Payload ID".
600Custom payload sequencePayload ID + operation name (≤16 chars) + arguments (≤128 chars) via prompt_text(); packed by make_sequence_data() and sent through send_tc_data.
601 / 602Capture MSI / SCANWAYTarget implied by the command ID; optional capture-parameter string as the raw data field.

payload_report() decodes both directions with framing::payload::decode: it prints the sent frame's type/cmd/len breakdown, the CCSDS summary, inner + TX/RX hex, then validates the reply — declared vs actual length, echoed command ID — and renders the single-character acknowledgement: 'A' green "command performed", anything else red. The payload server returns no telemetry, only this ACK.

xlink_flow() — the RF transceiver (main.cpp:1740)

Lists every XLINK-S TC with its spec ID and 32-bit event number, and shows the currently active product key (or a warning that the zero key will be NAK'd by real hardware). Accepts a menu number, XL-N, or the service name. GET/SET is decided per service: VERSION/HOUSE_KEEPING/XPA_INF are GET-only; IDLE, RESET, UART_BD_SAVE, IP_ADR_SAVE, RF_XMT_DATA, XMT_IDLE_FRM and GPIO_* are SET-only; the rest ask [g]et or [s]et?. SETs prompt for every field except product_key, service_event and Reserved fields, accepting enum names or numbers. The exchange goes through send_xlink_tc; the report shows TX/RX, the TM frame header when routed via the OBC, a ✓ ACK / ✗ NAK banner ("wrong key or bad params"), then the decoded response.

xlink_pick_key() lists the vendor catalog's (XmtSymbFreq, RcvSymbFreq) configurations from xlink_catalog(), applies the picked entry's 128-bit key to the Session and prints its capability flags — real hardware NAKs "ACCESS_VIOLATION" when the key doesn't match the transceiver's configured symbol rates.

11 · Rate-group LUT

The [g] binary rate-group LUT composer

The OBC autonomously polls subsystems on four priority tiers and packs the picked response bytes into 1280-byte Master-Frame subframes. What it polls and which bytes it keeps is defined by a binary look-up table that the operator composes, builds and uplinks from this menu. Two artifacts are produced, anchored at the project's config/ directory (blut_config_dir()):

  • rate_group_lut.bin — the OBC binary, the only thing ever uplinked;
  • rate_group_lut_bin_gs.json — the ground-only "twin" holding ids, names and pick params for logging/debug, and the resume state for later edits. It never leaves the ground.

Composer functions (main.cpp:2416–2758)

blut_print_summary()Per-tier "cmds, used / budget" lines (red when over budget) plus builder warnings and errors.

[s]end handlerStrict rule: only the binary crosses the link. Reads the .bin, frames it as 'XLUT' + u32 length + body, connects to obc_port+3, and prints the OBC's "OK…" or error reply.

The binary itself (see binary_lut_builder.hpp) is a 50-byte header (magic XLUT, version, segment sizes, entry counts, segment offsets, file length, CRC-16-CCITT signature) followed by entries of sync A55A · apid · flags · tc_len · pre-built native TC bytes · tm_raw_len · pick_count × {src_off, size, block_off}. Deliberately id-less: entry position within its segment is the only OBC↔GS link, protected by the shared CRC. The XLink product key from the loaded catalog is baked into replayed XLINK TC bytes. rate_group_csv.cpp parses the operator's CSV master list (tier,tc_id,subsystem,tc_name,picks, RFC-4180 quoting, per-row error reporting) into the same source JSON for the [i]mport path.

12 · Automation

Script mode and command history

run_script() (main.cpp:2140)

With --script FILE the CLI runs the file and exits. Each non-blank, non-# line is SUBSYSTEM TC_ID — the TC resolved by spec ID, then wire id, then name — plus a WAIT n command that sleeps n seconds. Every TC is sent with default-zero parameters through the same send_and_report() path (so preflight checks, dumps and decoding all still apply), and every problem is reported with its line number without stopping the run.

# example script
EPS EP-3
WAIT 2
ADCS 42
GPS LOG

show_and_replay_history() (main.cpp:2222)

The ! menu lists up to 10 recent commands with ages ("34s ago"), and re-sends the picked one: synthesized entries replay through their LOG-wrap / empty-payload path; ordinary TCs replay with default-zero parameters (the simple-and-safe choice — no interactive re-prompt).

13 · Supporting modules

The xdos_core pieces the CLI stands on

MIB — src/mib/mib.{hpp,cpp}

The Mission Information Base loads per-subsystem JSON files (mib/adcs.json, eps.json, gps.json, payload.json, xlink.json, ccsds_*.json…) into immutable structures: SubsystemDef → Message → Parameter, plus EnumType, Node (EPS boards with RS485 addresses) and ChannelInfo (the EPS power-channel map used throughout the UI). Lookups are O(1) by name, by (subsystem, direction, wire_id), and by (…, node, wire_id) — the node variant exists because EPS wire ids repeat across PDU/BMS/MPPT boards. by_param_id() accepts loose spec-ID input ("EP-019", "EP-19", "ep19", "19") and returns nullptr on ambiguity rather than guessing.

Payload codec — src/codec/codec.{hpp,cpp}

encode(msg, values) / decode(msg, payload) translate between JSON value maps and payload bytes using the message's parameter table. Two offset modes selected by Message.offset_unit: "bits" (ADCS/XLink — bit-packed LE) and "bytes" (EPS/GPS — byte-aligned LE). Scaled integers multiply on encode / divide on decode; ENUMs accept value or name; missing fields default to zero; variable-length trailing arrays (GPS HWMONITOR/PSRDOP/VERSION) decode greedily into a _array list.

Transport — src/transport/tcp_transport.{hpp,cpp}

TcpClient is a minimal blocking client: connect(host, port, timeout), mutex-guarded send, and recv(max, timeout) that returns when at least one byte arrives or the timeout/connection-loss hits. Bytes travel unmodified — all framing is the caller's job. (TcpServer in the same header serves the simulators, not the GS.)

XLink codec & keys — src/subsystems/xlink_{codec,keys}.{hpp,cpp}

encode_frame()/decode_frame() implement the monolithic XLink wire format: 16-byte LE product key, 4-byte service_event (top nibble GET/SET/ACK/NAK flag, low 28 bits event id), then a U32-word-aligned bit-packed data block — fields never span a word boundary, which is why the generic codec can't be reused. parse_key_hex() reads the "aabbccdd-…" key form. KeyCatalog::load() parses the vendor's per-device key file: serial number, MAC, unit model, and one KeyEntry (symbol-rate pair → 128-bit key + capability flags) per supported configuration.

EGSE — src/common/egse.{hpp,cpp}

Builders and parsers for the XGSE bench frames used by the PowerMonitor: make_req, make_kill_set, parse_eps_status, parse_obc_status, plus name tables (obc_state_name, eps_mode_name). EpsStatus carries kill, mode, orbit phase + remaining seconds, battery mV, SoC, effective channel mask and autonomous shed mask; ObcStatus carries the boot FSM state (Unpowered/Booting/Sequencing/On), countdown and sequence progress.

FlightConfig — src/common/flight_config.hpp

Header-only loader for config/flight.json with compiled fallbacks: OBC boot/stagger timings, the power-menu (name → EPS channel list) that seeds the PowerMonitor, the default-ON sequence, battery thresholds and shed policy, orbit phase durations, and the EGSE endpoints. bits() converts channel lists to 16-bit masks.

Colour — src/common/color.hpp

ANSI helpers used in every print: header/ok/err/warn/hint/addr and the set_tag/get_tag/act_tag trio; set_use_color(false) backs the --no-color flag.
